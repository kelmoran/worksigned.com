Usage

How to use WorkSigned

WorkSigned is a research platform and a signing authority that captures, signs, and seals everything you do so that the work — and who did it — is provable, while also providing enhanced privacy and protection from idea and data leakage. This page is the user's guide: how the platform is built, the modes it runs in, what every application on the platform can do, and what your own machine and browser need.

Alpha stage. WorkSigned is in alpha: individual application features and their capabilities may change as we build toward a stable release. The core of the platform — the proof chain, the sealing and signing of your work, and the data & security policy — does not change.

How it works

WorkSigned is one workspace that hosts every tool a researcher uses — code, documents, spreadsheets, slides, LaTeX, an AI assistant, and a funding ledger. Each tool opens in its own tab. What makes it different is the layer underneath: every action across every tool is captured, timestamped, hashed, and appended to one tamper-evident WorkSigned Record.

The design has three parts that work together:

  • Capture. The client records file state (every create, edit, save) and user state (clicks, keystrokes, app switches). These are the raw events.
  • Sign. Each event is content-hashed (SHA-256) and linked to the previous one, forming a hash chain. Milestones are additionally signed with a signing key so the chain is not merely tamper-evident but attributable.
  • Seal. When a file, document, or app session is closed or saved, its final state is sealed — the hash of that exact content is written to the WorkSigned Record so a verifier can later confirm the file has not changed since.

Because every tool writes to the same WorkSigned Record, the record is continuous: a paragraph typed in the document editor, a number entered in a spreadsheet, a line of code committed, a dollar logged in the funding tool — all on one signed timeline, in order, attributed to the person who performed them.

Operating modes

Two choices define how you run it: which client (browser or desktop) and where your files live (your storage, WorkSigned’s cloud, or your local machine). AI-assisted work runs on your hosted LLMs by default, or on a private model you control — the configuration and any on-prem sizing are covered on the Deployment page.

DimensionOptions

FilesYour storage (S3, NFS, SFTP, and more), WorkSigned Private Cloud, or your local machine (desktop app).

Every configuration produces the same kind of WorkSigned Record and the same verification. The mode changes only where the bytes live; it never changes what is captured or how it is sealed.

Local-first, with WorkSigned as the signer. The capture works on your own machine with no cloud involved. What the signing authority adds is the signature: your WorkSigned Record carries a signature that any third party can verify — not just a local one.

Website usage

WorkSigned can track and WorkSigned Record your activity on any website you work in — not just the built-in tools. This is how off-site research (papers, databases, dashboards, references you consult) lands on the same signed record as the work it informed.

  • Desktop version. Supports website URL tracking and ledgering directly — the desktop client captures which pages you visit and when, and appends them to the WorkSigned Record. No extra setup.
  • Web version. Requires the WorkSigned open-source browser extension, which performs the same URL tracking and ledgering from within your browser.
  • Both are open source. The desktop client and the browser extension are open source — you can inspect exactly what is captured and how it is sealed.
Captured website activity is a logged, attributable event like any other: which URL, when, and by whom — sealed to the same tamper-evident chain as files, edits, and spend.

The proof chain

The core idea: a proof of work is only as good as the process behind the file. A back-dated file can be forged; the sequence of keystrokes and clicks that produced it cannot. WorkSigned builds its chain around that principle.

Files are the starting point

The WorkSigned Record does not begin with a blank slate. Each project's files are the initial state — the baseline the WorkSigned Record is measured against. Every file is content-hashed on creation and on every save. Think of it as a Git-style repository where the object being tracked is the exact byte content, and the history is the sequence of user actions that moved it from one state to the next.

Clicks and keystrokes mutate the state

On top of the file baseline, WorkSigned records user actions as state transitions. A keystroke changes a cell or a line of text; a click changes which tool, file, or view is active. Each action is an event with a type, a payload (what changed, and where), a timestamp to the millisecond, and a hash linking it to the event before it.

The full picture of a project is therefore:

  • the set of files (content-hashed), plus
  • the ordered stream of user actions that produced and mutated those files, plus
  • the higher-level events — milestones, funding entries, app sessions — interleaved on the same timeline.

The state is verified when a file or app is closed

Verification is anchored at natural boundaries. When you close or save a file, or close an app session, WorkSigned seals that state: it computes the hash of the final content and writes a sealed event to the WorkSigned Record. A verifier later re-hashes the file and checks it against the sealed entry. If they match, the file is provably the one you produced at that moment; if not, the file changed afterward.

This gives you fine-grained and coarse-grained proof at the same time. Zoom out and the WorkSigned Record is the whole story — projects, milestones, spend, authorship. Zoom in on any single save and it is every keystroke, mouse move, and click that produced it, timestamped and hash-chained.

Examples of what is on the chain

  • File saves. Every create/edit/save, content-hashed and appended.
  • Keystrokes and mouse events. The raw input that produced a save — not just the resulting file.
  • App sessions. Which tool was open, when it opened, and when it closed (a state-verification boundary).
  • Milestones. Author-anchored checkpoints, e.g. "Baseline assay validated — 14 files signed."
  • Funding events. Every dollar logged against a grant, on the same timeline as the work it funded.
  • LLM interactions. The full AI-assisted conversation (prompts and completions), so model-generated work is on the record.
  • Email / chat interactions. Human and LLM correspondence is captured the same way — a claim of collaboration or handoff is verifiable, not just asserted.

Two researchers both contributing to the same file, a funding decision that came after a specific data point, an LLM draft that a human then edited — all of it resolves to "who did what, and when," down to the individual.

WorkSigned Record & events

Every project keeps one WorkSigned Record. It is append-only: entries are added, never edited or deleted. You cannot rewrite history because each entry's hash incorporates the previous entry's hash — change any entry and every hash after it breaks, which is immediately detectable.

How events are inserted

Insertion is a single, strict path. An event is produced by the client (a save, a keystroke, a milestone, a funding line), then:

  1. Structured. The event is serialized into a canonical form — type, actor, payload, timestamp, and any associated content hash.
  2. Hashed. The entry is hashed, and its hash includes the hash of the previous entry in the chain. This is what makes it tamper-evident and order-locked.
  3. Appended. The entry is written to the WorkSigned Record at the end. There is no update or delete operation in the format; a correction is a new event that references the one it supersedes.
  4. Optionally signed. Milestones and sealed states are additionally signed with the project's signing key, making them attributable (not merely tamper-evident).

Because the WorkSigned Record is a single ordered stream, "accounting" is just a subset of it. Spend events and work events live on the same chain, so a grant ledger and a research timeline are the same artifact — no separate accounting software, no way to reconcile one against the other by hand.

What a sealed entry looks like

// WorkSigned Record — project zinc-kinase (excerpt) seq 00004 ts 2026-03-07T16:31:04.882Z actor dr.chen type keystroke payload "0.042" -> cell B7 prev 0x7a11...c02d hash 0x2f38...91ab seq 00005 ts 2026-03-07T16:31:05.630Z actor dr.chen type keystroke payload "+/-0.003" -> cell B7 prev 0x2f38...91ab hash 0x8c40...33e1 seq 00006 ts 2026-03-07T16:31:09.114Z actor dr.chen type sealed file results_v1.csv content sha256 b2e4...44aa prev 0x4410...6b77 hash 0xde02...91cc // signed // verify: re-hash results_v1.csv, walk the chain from a // trusted anchor. Any break = tamper detected.

The sealed event is the anchor a verifier uses: it ties a specific file, with a specific hash, to a specific moment and a specific person, with a chain of input events behind it showing exactly how that content was produced.

Applications

Every tool on the platform

Each application opens in its own tab and writes to the same WorkSigned Record. Below is what each one does.

Code editor

A full-featured source editor for any text-based file — Python, R, shell, JSON, TOML, and more, with syntax highlighting, multiple open files, and search. Every save is content-hashed and appended to the WorkSigned Record, so the evolution of a script or config is fully recorded.

  • Multi-file tabs with per-file language detection and syntax highlighting.
  • Find/replace across the open buffer.
  • Every save sealed to the WorkSigned Record; every edit attributable.
  • Works alongside the live runner to go from edit to execution in one place.

Live runner

Code you write in the editor runs inside the platform — not just saved, but executed. This is what "runs live" means: the environment is part of the toolchain, so the inputs, the code, and the outputs are all captured together. Running a script or a cell is itself a logged event.

  • Execute code directly in the workspace and capture stdout/stderr to the record.
  • Outputs (plots, tables, result files) are sealed like any other artifact.
  • Reproducible: the exact code + the exact run are both on the WorkSigned Record.

LaTeX

Write LaTeX and compile it to a rendered paper in the same tab — source on one side, typeset output on the other. Both the .tex source and the compiled PDF are sealed, so the paper you submit is provably the one you authored.

  • Side-by-side source editor and live-compiled preview.
  • Common document classes and equation support.
  • Inline animations — embed animated figures and motion directly in the document (e.g. time-evolving plots, simulations, and interactive demos), rendered inline next to the typeset text.
  • Source and rendered output both content-hashed onto the WorkSigned Record.
  • BibTeX / bibliography and figure inclusion.

Documents

The document editor is a full-featured word processor compiled to run in the browser. It is not a reduced web form — it is the full writing environment. The feature set:

  • Text & formatting. Rich text; fonts, sizes, weights, styles; character and paragraph formatting; inline styles.
  • Styles & templates. Built-in and custom styles; apply/define template documents.
  • Lists & numbering. Bulleted, numbered, and multilevel lists; captions and numbered headings.
  • Headings & outline. Heading styles that drive the document outline and navigation.
  • Tables. Create and edit tables with merged cells, borders, and alignment.
  • Images & graphics. Insert images and vector objects; resize, crop, and wrap text around them.
  • Equations. Insert and edit mathematical formulas.
  • Footnotes & endnotes. Insert, edit, and reference notes.
  • Cross-references & bookmarks. Named bookmarks and automatic cross-references that update.
  • Mail merge. Merge a document with a data source for bulk generation.
  • Find & replace. Including regular expressions and whole-word matching.
  • Spelling & grammar. Spell check, thesaurus, and language settings.
  • Redlines & comments. Track changes, accept/reject edits, and threaded comments — the whole review cycle is captured on the WorkSigned Record.
  • Page layout. Margins, headers/footers, page numbers, sections, columns, page breaks.
  • TOC & indexes. Automatic table of contents, table of figures, and indexes.
  • Export. Save to DOCX, ODT, and PDF.
  • Production-grade office tool. A full-featured, native document editor — the everyday writing and formatting features researchers actually use.

Sheets

The spreadsheet editor is a full-featured spreadsheet engine in the browser. Your results, analysis, and tables — versioned and verifiable. The feature set:

  • Cells & data. Enter and format numeric, text, date, and currency values; multiple sheets per workbook.
  • Functions. The standard function library — math, statistics, financial, text, date/time, and lookup.
  • Formulas & references. Cell references, ranges, absolute/relative references, and cross-sheet references.
  • Tables & sorting. Filterable data ranges; sort by one or more columns.
  • Charts. Bar, line, pie, scatter, and more, built from sheet data.
  • Conditional formatting. Highlight cells based on value or formula rules.
  • Data analysis. Pivot tables, subtotals, and data-series tools.
  • Cell styles & number formats. Named cell styles and custom number/date formats.
  • Validation & protection. Input validation and sheet protection.
  • Find & replace. Across the workbook, with options.
  • Import / export. XLSX, CSV, ODS, and more.
  • Production-grade office tool. A full-featured, native spreadsheet — the everyday data and analysis features researchers actually use.

Slides

Assemble presentations and figures, ready to defend your work to reviewers. The feature set:

  • Slides & masters. Multiple slides; slide masters and layouts for consistent design.
  • Placeholders & text. Title/body placeholders; rich text and bullet formatting.
  • Shapes & images. Draw shapes, insert images and charts from your sheets.
  • Transitions & animations. Slide transitions and object animations for delivery.
  • Notes & handouts. Speaker notes and handout layouts.
  • Presentation mode. Full-screen delivery with a presenter view.
  • Export. PPTX, ODP, and PDF.
  • Production-grade office tool. A full-featured, native presentation tool — the everyday slide and layout features researchers actually use.

AI Chat

Work alongside an AI research assistant in a dedicated chat. The assistant can help reason, draft, and analyze — and the entire conversation is on the record, so AI-assisted contributions are attributable, not a black box.

  • Streaming conversation with the configured LLM (dedicated, public, or private).
  • Full transcript captured to the WorkSigned Record — prompts and completions alike.
  • Works across the project: the assistant can read the working set you give it.
  • Model is your choice — including a fully local, on-hardware model.

Funding ledger

Log spend against grants as you go. Every dollar lands on the same signed timeline as the work it produced, so what was done, by whom, and at what cost is one artifact.

  • Record line-item spend and tie each to a grant and a purpose.
  • See total committed vs. spent per grant.
  • Spend events are sealed like any other WorkSigned Record entry — auditable and immutable.
  • Answers grants and audits from the same WorkSigned Record as the research.
Research & collaboration

Proof replay

Watch the work happen. Proof replay reconstructs the recorded timeline of a project and plays it back — every event, in order, on its original timestamps. This is the human-readable face of the WorkSigned Record: the same data a verifier walks, shown as a play-through.

  • Reconstructs the project timeline from the WorkSigned Record.
  • Plays back events in order, on their original timestamps.
  • Zooms from milestone-level to individual-keystroke detail.
  • The verification story, visualized — not just a hash list.

Notebooks

Run Jupyter notebooks directly in the platform. Cells, code execution, plots, and file access all happen in the workspace — and every cell edit and execution is captured on the WorkSigned Record, so the notebook you share is provably the one you ran.

  • Markdown + code cells with live in-browser execution.
  • Python notebooks today; Julia and R kernels are coming soon.
  • Inline plots, tables, and output rendered in place.
  • Cell history and file reads/writes recorded to the WorkSigned Record.

Protected Search

The privacy front end of the platform. A single query is sharded into harmless parts and the parts are dispatched across separate search engines, AI providers, and IP addresses, then synthesized privately. No single request reveals the shape of your project, so your intent never leaks.

  • Query sharding — the full question is never sent as one pattern.
  • Dispersal across multiple engines, providers, and exit IPs.
  • Query translation so individual fragments don't expose the topic.
  • Private synthesis of the result back in the workspace.
  • Every search is itself a logged, attributable event.

Image editor

Work on figures, screenshots, and data images in a full raster editor — the same environment a lab uses to prepare a panel for a manuscript, sealed to the WorkSigned Record when you save.

  • Drawing and editing tools: pencil, brush, eraser, and more.
  • Layers — build complex figures in separable, editable layers.
  • Selections and transformations (crop, resize, rotate).
  • Colors, effects, and standard image operations.
  • Open, edit, and export common formats; saves sealed to the WorkSigned Record.

Git tree

See the version history of a project's files as a tree. WorkSigned tracks the repository so you can move through commits, inspect what changed between them, and tie each state to the WorkSigned Record — provenance for every revision, not just the latest file.

  • Branch and commit tree for a project's files.
  • Diffs between revisions to see exactly what changed.
  • History per file — when and by whom a line or block changed.
  • Complements the WorkSigned Record: the WorkSigned Record is the fine-grained WorkSigned Record, the tree is the revision history.

Email

Compose and send mail from inside the platform under your WorkSigned identity. Because it lives on the same record as everything else, an email you send about the work is part of the proof — a handoff, decision, or claim of collaboration is verifiable, not just asserted.

  • Compose and send as your WorkSigned identity.
  • Attachments and standard message features.
  • Outbound messages captured on the WorkSigned Record, timestamped and attributable.
  • Pairs with Team chat and AI Chat as the platform's on-record communication.

Team chat

Converse with your team about the work — in the same workspace where the work happens. Human conversations, like everything else, are on the record, so claims of who said what and when are provable.

  • Project-scoped conversations with your team.
  • Threads and message history within the workspace.
  • Messages captured to the WorkSigned Record — attributable to the individual.
  • Distinguishes human chat from AI Chat: both on-record, clearly separated.

Calendar

Plan the work around the tools that produce it. Experiments, milestones, submission deadlines, and meetings live next to the research — and events you set are on the same record as the work they point to.

  • Events and schedules for experiments, milestones, and deadlines.
  • Meetings and lab coordination alongside the work they reference.
  • Created events are logged to the WorkSigned Record, tying the plan to the execution.
