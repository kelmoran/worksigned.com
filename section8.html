Getting Started

The full walkthrough

The whole pipeline in 90 seconds: connect the work, sign each day, seal it, and hand the record to anyone who should check it.

Overview

Getting WorkSigned up to speed on your project is a one time setup. After that, the software runs in the background and signs your work automatically. Here is what that setup looks like, step by step.

Linking up data sources

A mount is how WorkSigned connects to a data source. When you mount a source, its files and databases appear in the explorer panel on the left side of the interface, as if they were local files. WorkSigned then watches every file on that mount and records its content hash into the project record. Supported sources include: local folders, SSH/SFTP servers, S3, Azure Blob, GCS, Google Drive, DSpace, iRODS, and databases (PostgreSQL, MariaDB, SQLite).

To link up a source:

1. Open the explorer panel. Right-click on the project name and select "Mount Storage…".

2. Choose the source type (local path, SFTP, S3, etc.) and enter the connection details (host, credentials, bucket name, etc.).

3. The mount appears in the tree. Expand it to confirm the files are visible. That is all - WorkSigned is now tracking that source.

Repeat for each source the researcher uses. A typical setup might be: one local mount for the project folder, one S3 or Drive mount for shared data, and one database mount for structured results.

Using the tools

Once the data is linked, the researcher works in the built in tools exactly as they would in any other application. Click a file in the explorer and it opens in the appropriate tool: a .py file opens in the code editor, a .docx in the document editor, a .tex in LaTeX, a .png in the image viewer. The researcher reads, edits, and saves files without leaving the client. Every save is captured and signed.

The AI chat, web search, and other tools work the same way. Open them, use them, and the activity is recorded into the project record alongside the file work.

Hooking up email

Email is connected through the institution's local witness server. The researcher configures their mail provider (IMAP/SMTP or API) once, and after that all email sent or received through the WorkSigned client is witnessed and signed into the record. This means handoffs, decisions, and collaboration claims made over email are on the signed timeline, not just in an inbox that anyone could delete.

Generating a record

The record is not something the researcher manually generates. It builds itself. Every file save, every AI interaction, every email, every web search - each one is appended to the project record as it happens. At the end of each day, the record is sealed: a cryptographic signature is applied to the day's entries and a timestamp is issued by the remote signing server. The result is a signed, tamper-evident chain that shows exactly what happened, when, and who did it.

When the researcher is ready to produce evidence (a dispute, an audit, a publication requirement), the record is handed to the verifier. The verifier checks the signatures and timestamps, and the chain confirms the work was done as claimed.

Insights generated from the record

Once the record is built, WorkSigned can generate several documents and analyses from it. These are not separate tools - they read the same signed record and produce structured output for specific purposes.

Calendar. The record as a month of days. Each day shows its seal (the Merkle root, signed and timestamped). Click a day to see the files, hashes, and signed digest for that day.

Timeline. The record over time: each file version as a node, the change between versions as the edge. Goals are placed at the first recorded version that contains their topics, giving a prior-use / conception data point.

Snapshot. The current-state research map: one node per file (final state), with goals, subgoals, and topics connected by typed edges.

Patent. A lawyer-facing patent draft (specification sections, claims, and a dated artifact ledger) assembled from the research map and the signed record. An attorney must finalize it.

AI Disclosure. A report showing how much AI contributed to the research and what it contributed. Which AI tools were used to achieve which goals, and which artifacts contain AI-generated content.

Gap Analysis. A 5-dimension assessment (completeness, sufficiency, authenticity, relevance, timeliness) of whether the record is sufficient to support the research goals.

Legal Standards. A check against 6 current legal standards for AI-IP (from 2023-2026 case law and guidelines). Shows which standards the record meets and which it does not.

Search. Find recorded days by text query or by tag, with the signed day record inlined under each hit.
