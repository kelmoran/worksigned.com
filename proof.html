How the proof works

A WorkSigned Record is a record of a researcher’s work that anyone can check for themselves — without relying on WorkSigned’s servers or its word.

The one idea. WorkSigned does not read or upload the researcher’s files. It signs a 32-byte fingerprint of the WorkSigned Record. Because the fingerprint changes completely when even one byte changes, “the authority signed fingerprint H” is the same as “the authority signed this exact record.”

How it works

The whole process in five steps. The only technical word used is hash — a fixed-length fingerprint of the work that changes completely when even one byte changes.

1
Researchers work
Researchers edit and save files in their project, the normal way.
2
The work is recorded
The platform logs the project’s activity — edits, saves, terminal commands, chat messages — into the researcher’s WorkSigned Record. It stays on the researcher’s machine.
3
One hash of everything
On each seal, the fingerprints of all files are folded into a single hash. That hash is the only thing that leaves the researcher’s servers — no files, no names, no logs.
4
Independently time-stamped and signed
An independent authority signs the hash together with the time, using a clock outside anyone’s control. The time and the hash cannot be changed without breaking the signature.
5
The seal is kept
The researcher (or the institution) stores the hash, the time, the signature, and the authority’s public key. It does not live on WorkSigned’s servers.
# The project’s activity, as the platform records it Wed 09:14:02 methods.tex key typed \frac{a}{b} Wed 09:14:41 methods.tex save file saved Wed 11:02:33 terminal cmd python analysis.py Wed 15:40:55 chat msg “baseline confirmed” Thu 08:22:19 results.csv save file saved → every event, in order, is the WorkSigned Record — not a single snapshot

At sealing time, exactly one value — the single hash above — is sent to the signing authority. Nothing else crosses the boundary: no file content, no file names, no keystrokes, no chat, no record. The hash is a fixed-length number with no way to read back from it.

What it proves

The work existed
At time T
At time T, the researcher had this exact body of work — the files, the edits, the sequence — and it has not changed since. Change one byte and the seal no longer holds.
The files were never seen
Only the hash
The authority signed a fingerprint, not the files. The content never left the researcher’s servers, and WorkSigned does not store it.
Anyone can check it
Offline, no WorkSigned
A journal, funder, or court verifies the seal themselves, with only the public key and the record. No call to WorkSigned’s servers, no word from WorkSigned.
Stated plainly. A seal is strong, independent evidence of when the researcher had the work — the files, the edits, and the sequence, at a specific time. It does not claim the work was original, and it is powerful evidence, not a legal determination. Its strength is in the process: a complete, time-anchored record of how the work developed, which is hard to fabricate.

Why it can’t be forged

To fake a sealed record, an attacker must either break the fingerprint — find different work that produces the same hash — or steal the signing key and the independent time-stamp at the same time. Breaking the fingerprint is far beyond any realistic computing power; no practical shortcut is known. The honest weak point is the second route: the key and the time-stamp, which is why the key is kept in a hardware vault and the time comes from an independent party.

# Rough estimate (a, ab, abc, …): forging one sealed day • matching a sealed fingerprint by luck → ~1 in 10^77 per attempt • all the computing in the age of the universe → ~10^35 attempts → still fails by ~40 orders of magnitude (rough estimate, not an exact answer)

Built on open standards

The record is not a proprietary format; it is assembled from published, open standards, so a verifier checks the work against the standard itself rather than trusting WorkSigned. An independent third party provides the time, so the clock is outside anyone’s control in a dispute. The signing code and its append-only logs are auditable: anyone can confirm exactly what produced a given seal, and the private key never leaves the authority. And it is lightweight — because only fingerprints are stored, the authority keeps a few hundred bytes per seal, never the researcher’s files.
