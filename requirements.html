System requirements

WorkSigned runs as a client that captures, signs, and seals your research trail. The client is lightweight; the heavy work (large LLM inference, file storage) is offloaded to your chosen backend. The figures below cover a comfortable research workstation. Higher values improve headroom for local LLMs and large data sets.

Web browser Ranked by feature support for the built-in office suite and code editor.

The platform runs entirely in the browser. The document, spreadsheet, and presentation editors are compiled to WebAssembly and rely on shared-memory features that are enabled in all modern browsers.

Enable hardware acceleration and keep the browser up to date. Cross-origin isolation is required for the office suite and is served automatically by WorkSigned — nothing to configure.

Local LLM endpoint Optional. Run your own model for fully private inference.

You may point WorkSigned at a local model endpoint instead of a cloud LLM. WorkSigned speaks the OpenAI-compatible chat-completions API, so any server that implements it works — including llama.cpp, vLLM, Ollama, or another self-hosted inference server.

SettingValue
APIOpenAI-compatible /v1/chat/completions
StreamingSSE streaming (recommended)
Example base URLhttp://127.0.0.1:8080/v1
HardwareDepends on model size. A GPU with 16–24 GB VRAM comfortably serves 7B–13B models; CPU-only works for smaller models.
Local LLM mode keeps all prompt and completion data on your hardware. Nothing is sent to an external provider.

Private cloud LLM WorkSigned-dedicated models, or your own.

By default WorkSigned routes AI-assisted work to dedicated LLMs operated by WorkSigned — not frontier models that train on your data. Institutions that require on-premises inference can direct the platform to their own private LLM endpoint (see the local-endpoint section); the same toolchain, prompts, and sealed-record behavior apply either way.

File storage Choose where project files live. Each mode has a different setup footprint.

WorkSigned signs and seals whatever it writes, regardless of where files are stored. The four options differ in setup and access:

OptionSetupDescription
1. WorkSigned Private CloudNoneFiles stored on WorkSigned infrastructure. Fully accessible and auditable by the user. Default cloud mode.
2. Custom Private CloudBackend proxy requiredConnect WorkSigned to your own file server (S3-compatible or NFS). A backend proxy must be configured to bridge the platform to your storage.
3. Local machineDesktop app install requiredFiles stay on your workstation, captured by the desktop client. Maximum privacy; requires the desktop app.
4. No files (browser only)NoneLight usage entirely in the browser, including JupyterLite for notebooks. No external storage required.
