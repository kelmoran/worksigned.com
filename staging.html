Who plugs in, and how

WorkSigned is a signing layer. It signs the fingerprints in your backup / version-control and stores only a tiny signed record (hash + signature + pointer). Three people plug in: the researcher, IT, and administration. Each has a different job.

Summary: the researcher picks three locations (live files, backup/version-control, signed records), IT protects the backups the proofs point to, and administration chooses how much to run. Only the backup/version-control layer gets signed; WorkSigned stores only the signed records; nobody re-hosts your data.

The three things

There are exactly three distinct things. You pick the location for each (any mount, local or remote, yours or IT’s). Picking these three is the only thing you ever configure. Only one gets signed, and WorkSigned stores only one.

Live files are ephemeral and are not signed. WorkSigned signs the backup / version-control layer (what already holds the work) and writes only the tiny signed records.
1
Live files
Your working directory: the files as they are right now. This is ephemeral state; it changes constantly and is not signed. WorkSigned points at it to know where the work is, but the proof does not depend on it.
2
Backup / version control
Git, backups, or tape: the durable record of the work. This is what gets signed. A proof depends on these bytes, so it must be retained and accessible.
3
Signed records
The hashes + WorkSigned’s signature (and the daily-anchored log). This is tiny and is the only thing WorkSigned writes. Local disk or a remote mount both work.

1 · The researcher

The researcher’s only job is to point WorkSigned at three places and then keep doing their work. The core proof requires no new app; the signed record comes from what already exists. Optional layers (AI proxy, mail, in-app editor) activate only if the researcher opts in.

read / sign pointer (no copy) opt-in capture
Green is the always-on core path. Amber is the opt-in layers that add process and priority evidence on top.

2 · IT

IT runs the backup & retention side. The interface shows the hot backups (the ones referenced by a signed record). It also synchronizes with the researcher side: if IT deletes a hot backup, the researcher sees it immediately, so a proof never points at nothing. The retention policy gets one rule: do not delete what a proof depends on.

sync / status deletion → alert signed record
IT keeps running its existing backups. WorkSigned marks the backups referenced by a signed record as hot and immediately surfaces any hot deletion to the researcher.
How IT’s retention changes: IT operates nothing new. The one added rule is never delete a hot backup without telling the researcher. The interface marks backups hot or cold, and a deleted hot backup alerts the researcher immediately.

3 · Administration

Administration’s job is choosing how much to run. WorkSigned supports any backup scheme, and you can switch every dimension independently: run just the core, add layers, manage the backups yourself or through IT, or turn backups off entirely.

always on optional layer either way
Blue covers the either-way choices (any scheme, any manager). Amber covers the optional add-ons. The green core does not change with any dial; that is the plug-and-play guarantee.
Plug and play: any backup scheme (or none), IT-managed or self-managed, more backups or fewer, every optional layer on or off. The signing core works in every combination; administration sets the dials and it runs.
